# Northstar site: design-repo

A machine-validated PageSpec system for the Northstar marketing site. It gives a generator
three things: **what can be used** (tokens, primitives, components, section contracts),
**how it can be combined** (templates, compatibility graph, schema) and **how it must behave**
(motion patterns with locked reduced-motion fallbacks, per-breakpoint responsive notes,
copy budgets). Every value cites real evidence; nothing is invented.

## Read this first: what the source is (and is not)

1. **The original is real; the brand is not.** The source project (the parent folder of this
   repo) is a layout-and-motion clone of a real, live commercial site (superhuman.com), rebuilt
   under a **fictional** brand, **Northstar**.
   - All copy in the source is independently written placeholder copy.
   - All logos, product mockups, avatars and badges are original invented SVG illustrations
     (`src/illustrations/`). None reproduce the real company's assets.
   - Fonts are OFL substitutes: Hanken Grotesk, Source Serif 4 and JetBrains Mono, standing in
     for the original's proprietary faces.
   - **Generation rules** (`assets/asset-roles.json` → `globalProhibitions`, `generationPolicies`):
     never reproduce the original company's logos, product screenshots, marketing copy or fonts;
     never use real third-party logos or app icons, real certification marks, or photos or
     likenesses of real people. Compliance-critical roles are pinned to one policy and checked
     by `verify_all.py` (customer logos → `reuse-registry-or-placeholder`, badges →
     `placeholder-only`, avatars → `illustrated-person-only`, integration strips →
     `invented-marks-only`, wordmark and lockups → `must-reuse-exact`).
   - Copy budgets (`maxChars`/`maxWords` on every text field) come only from the specs' measured
     *lengths* (original length × 1.1; words = ceil(chars / 4.5)). No original or spec text is
     pasted or paraphrased here. Rule `FORBIDDEN_CONTENT` rejects PageSpecs that name the
     original company.
2. **Excluded material.** The user's saved copy of the original page (`reference/`, a sibling of
   the site folder) and the raw measurement dumps (`.playwright-mcp/`) were not used as content,
   are not cited, and are not packaged. `verify_all.py CITATIONS` rejects any citation into them.
3. **Unbuilt routes.** The router has 7 real pages. Every other path renders `ComingSoon`
   ("This page is being built."), a deliberate placeholder, **not** a page shape: it has no
   template and must never be reproduced. A future wave will add team, use-case, store and
   company pages; they are out of scope for this snapshot (`templates/routes.json`, rule
   `OUT_OF_SCOPE_ROUTE` warns).
4. **Snapshot under concurrent edits.** Two other agents (illustrations for /mail and /docs; a
   pixel audit of components and tokens) were editing `src/` while this repo was built. The repo
   was regenerated from the post-audit source and re-checked against current source immediately
   before packaging (`verify_all.py --strict-source`: routes, each template's JSX source order,
   ui component coverage, stack versions, and every citation's line range and expected text).

Template nodes are structured (`section`, `variants`, `required`, `repeatable`, `min`, `max`,
plus `realCount`/`realVariant`/`realBackground` from the real page). The validator matches a
PageSpec against its declared template's node list in order (`TEMPLATE_SEQUENCE`), keyed on
(section, variant).

## Using it to generate a page

1. Pick a template from `templates/templates.json`; keep its node order.
2. For each node, fill `content` per `sections/<id>.json` (stay inside `maxChars`/`maxWords`),
   choose a `background` from the contract's `allowedBackgrounds` and the matching `context`,
   and copy the motion object for the allowed pattern from `compatibility/motion-patterns.json`
   (with its locked `reducedMotionFallback`).
3. Media fields take `{slotId, assetRole}`; the role decides what may be drawn (`assets/asset-roles.json`).
4. Validate: `python3 -I schema/semantic_validate.py my.pagespec.json` (exit 0 = no errors).

## Motion at a glance

`compatibility/motion-patterns.json` is the closed list (14 patterns). Highlights:

- **Hero demos.** Product-page heroes (/mail, /docs, /go) use `hero-video-loop`: infinite,
  viewport-gated loops (cycles in `cycleMsBySlot`: 35.9s, 28.3s, 10s), static complete frame under
  reduced motion. The homepage carousel art is `hero-video-oneshot`: one 7s timeline per slide,
  never looping. Each is rejected where the other belongs.
- **/go pinned text** (`sticky-pinned-text`) is a CSS scroll-driven animation on a named
  view-timeline, with a JS scroll/rAF fallback where `animation-timeline: view()` is unsupported.
  Only at ≥640.02px under no-preference.
- **FAQs** are single-open everywhere (`faq.accordion` `mode` is pinned to `single`).
- **Smooth scrolling** is site-wide under no-preference (`siteWide.smoothScroll`); route
  changes still jump to the top.

PageSpecs carry no per-instance token overrides; styling belongs to the contracts
(`tokens/llm/token-policy.json` → `overrides`).

## Breakpoints

Measured min-widths: **640.02px**, **1080.02px**, **1280.02px**, **1440.02px** (no md tier;
640.02-1080.02 is one layout family). Every section lists its per-breakpoint changes in a
structured `responsive` array; `verify_all.py` checks all four are covered.

## Verification

```
python3 -I schema/semantic_validate.py        # example: schema + semantic rules
python3 -I schema/tests/adversarial_test.py   # controls pass, every mutation rejected
python3 -I extraction/verify_all.py           # everything (add --strict-source next to the site)
python3 -I extraction/prove_drift.py          # each drift check fails on an injected defect
```

Requires Python 3.9+ and `jsonschema` (install into a virtualenv). Scripts derive their paths
from their own location; without the sibling site folder, citation and source-drift checks
warn instead of failing.

## Groundwork spot checks

Details and citations in `extraction/measured-values.json` → `spotChecks`. In short:

- CLONE_SPEC says the homepage logo strip never rotates; current src rotates it (as the later
  /mail and /plans measurements do). The contracts follow src.
- plans.md measures the floating-header CTA label at 14px; the pixel audit set 16px. The contracts follow src.
- The `button-mid` type role is declared in tailwind.config.js but unused.
- Spec component names (StatBand, QuotePair, SplitMedia, CtaBlock, FeatureColumns,
  TestimonialPair) differ from src; contracts cite the real src locations.
- The copy strings in CLONE_SPEC.md, specs/plans.md and specs/enterprise.md now reference the
  independently written implementation in src/data (1.1.0); budgets still use only the measured
  original lengths, and no spec copy is quoted in this repo.
- The /mail compatibility line names two invented mail clients (Wrenmail, Driftpost), renamed
  in src/data/mail.js from names that could match real products.
- The pixel audit flipped /mail rows 6–10 to start media-right; the example follows.
- site/ia.json (a separate IA pass) independently arrives at the same 7 route-level templates.
- 1.2.0 motion pass, verified against src: product-hero loops vs the homepage one-shot, the /go
  view-timeline pinned text with its JS fallback, single-open FAQs everywhere, and site-wide smooth
  scrolling (spot checks `product-hero-loops`, `sticky-row-view-timeline`, `faq-single-open`,
  `smooth-scroll-site-wide`).

## Known gaps

- The FloatingPlanHeader transition is not gated on reduced motion in src. The contract locks
  the recommended `instant-show-hide` fallback and records the gap.
- Viewports above 1440 were never measured.
- In-page smooth-scroll durations (about 0.79s for the /plans compare jump) are chosen by the
  browser, so no duration is pinned for `smooth-scroll-anchor` or `siteWide.smoothScroll`.
- Homepage copy uses h2 for the carousel (no h1). The structure is kept as-is.
